# Token Economics

> Token-cost engineering, baked in — not bolted on. Mythos-class model pricing (≈$10 / million input tokens, ≈$50 / million output tokens as of 2026-06) makes naive prompt bloat genuinely expensive at scale. The library ships ten strategies that, in combination, keep the cost of always-on context low and concentrate spend on demand.

This document is the operational expression of [ADR 0005 — Token Economy Architecture](./adr/0005-token-economy-architecture.md). Phase 6's `registry-ci.yml` enforces the constraints.

## The two-layer contract (single biggest lever)

Every rule has **two fields** that matter for token economy:

| Field | Layer | Always-on? | Loaded when | Budget |
|---|---|---|---|---|
| `summary` | **Layer 1** | Yes (Tier 0) or scoped to glob match | (Tier 0) always; (others) when `scope.globs` match files in agent context | **≤300 chars** (~80 tokens) |
| `content` | **Layer 2** | No | (a) agent explicitly fetches by ID, (b) `scope.globs` match AND rule is in agent's active list | Bounded by template; per-rule discipline; no hard limit but warned >2K tokens in CI |

**Reduction.** ~50 rules × ~80 tokens = ~4K tokens for the always-on layer. Shipping full content into always-on context would be ~50 rules × ~800 tokens = ~40K tokens — a ~10× blow-up. Schema enforces Layer 1 strictly (CI blocks `summary > 300 chars`); Layer 2 is reviewed by convention.

## The ten strategies

### Strategy 1 — Two-layer rule loading

As above. Layer 1 always-on, Layer 2 on demand. **The single biggest cost lever** — encoded directly in `registry/schemas/rule.schema.json` and enforced by CI.

### Strategy 2 — Scoped activation via globs

Non-critical rules set `scope.always_apply: false` + narrow `scope.globs` so they activate only when matching files are in agent context.

```yaml
scope:
  always_apply: false        # default
  globs: ["**/*.ts", "**/*.tsx"]
  exclude: ["**/test/**", "**/node_modules/**"]
```

Cursor's `.mdc` adapter supports `alwaysApply: false` natively. AGENTS.md adapter writes glob-scoped sections. Copilot adapter writes only the index entry; per-glob activation happens at IDE evaluation time.

**Tier 0 (~5 rules, `always_apply: true`):**
- `no-hardcoded-secrets`
- `prompt-injection-prevention`
- `agentic-human-approval`
- `ai-audit-logging`
- `mcp-server-safety`

Everything else is scoped.

### Strategy 3 — `registry/INDEX.md` as cheap discovery

A single small file (~3K tokens) lists every rule ID + `summary` + tags + globs. Agents read INDEX.md **once per session** to discover what's available, then fetch full rules on demand.

Properties:
- Auto-generated by `make index` from rule files; cannot drift.
- CI workflow `registry-ci.yml` regenerates INDEX and fails on stale diffs.
- Adapter `cursor` references INDEX directly; Copilot adapter writes `copilot-instructions.md` as a ≤2K-token alias.

### Strategy 4 — Subagent token budgets

Every subagent declares an explicit budget:

```yaml
token_budget:
  input_max: 12000           # system + context window
  output_max: 4000           # max response
  warn_at: 0.8               # CI warns at 80% of budget
```

`registry-ci.yml` uses `tiktoken` (cl100k or model-specific encoding) to count:
- Each subagent's system prompt + first-turn user prompt.
- Each rule's `summary`.

CI behaviour:
- `summary > 300 chars` → **block**.
- Subagent prompt > 80% of declared budget → **warn**.
- Subagent prompt > 100% of declared budget → **block**.

### Strategy 5 — Inheritance (`extends:`)

Per-language rules `extends:` cross-language parents and ship only the language-specific delta:

```yaml
# registry/rules/coding-standards/per-language/python-security.rule.yaml
metadata:
  id: python-security
extends: secure-deserialization      # cross-language parent
summary: "Python-specific deserialisation: never unpickle untrusted data; prefer JSON; restrict YAML loader to SafeLoader."
content: |
  # Python deltas only — parent covers principles, BAD/GOOD generically.
  ...
```

Framework specs `extends:` language rules, picking up an extra delta. Net effect: ~30–50% smaller per-file payloads vs. duplicating guidance, and zero risk of drift between parent and child.

### Strategy 6 — Structured findings as default output

Subagents emit **SARIF or JSON-lines** by default. Prose explanations are on-demand (per-finding `?explain=true` flag). This is the largest source of avoidable output bloat — a SARIF finding is ~40 tokens; an equivalent natural-language explanation is ~400 tokens.

### Strategy 7 — Headless-first for pre-commit / CI

`hooks/pre-commit.sh` invokes **Tier C runners** which spend zero LLM tokens by default. LLM is consumed only when:

- A developer interactively asks for an explanation in an IDE (Tier A).
- A consumer opts into prose remediation via `$SECUREAI_LLM_ENDPOINT` (typically local Ollama / vLLM).

This concentrates LLM spend on demand, not on every keystroke or commit.

### Strategy 8 — Cache-stable ordering (free win)

KV-cache prefix hits cut input cost by ~90% empirically for repeat invocations against the same context prefix. The library makes prefix stability a binding contributor rule:

- **YAML field ordering** is frozen by schema. Rule authors do not reorder top-level fields.
- **Markdown section ordering** is frozen by template: Principle → Rationale → BAD/GOOD examples → Checklist → References.
- **INDEX.md row ordering** is alphabetical by `id` per category.

ADR 0005 explains the rationale. Contributors are reminded in [`CONTRIBUTING.md`](../CONTRIBUTING.md) Rule-author checklist.

### Strategy 9 — Adapter-side compression

Each adapter is tuned to the smallest viable always-on payload for its IDE:

- **Cursor adapter** — `.mdc` frontmatter + `summary` inline. Full `content` resolved via `@rule:<id>` only when scope triggers. ~500 tokens per file.
- **Copilot adapter** — writes only `.github/copilot-instructions.md` as a ≤2K-token INDEX. Per-category Copilot files under `.github/copilot/` are referenced but not inlined.
- **AGENTS.md adapter** — glob-scoped sections, `summary` inline. Full content referenced.

### Strategy 10 — Measurement hooks for the roadmap

Subagents emit JSON-lines audit entries with `token_in` + `token_out` per invocation to `.securecode/audit.log`. Zero infrastructure cost (file write). Feeds the M1 telemetry dashboard (see [`docs/MYTHOS.md`](./MYTHOS.md)) — measurement exists in v1 so baselines are available when M1 lands.

## Net token-economy targets

| Surface | Budget | How enforced |
|---|---|---|
| `.github/copilot-instructions.md` (always-on) | ≤ 2K tokens | `registry-ci.yml` token-budget step. |
| `AGENTS.md` (always-on summaries) | ≤ 4K tokens | Same. |
| `registry/INDEX.md` | ≤ 3K tokens | Same. |
| Each subagent system prompt | ≤ 1.5K–2K tokens (per declared `token_budget.input_max`) | Same; warn at 80%, block at 100%. |
| Cursor `.cursor/rules/<id>.mdc` per file | ≤ 500 tokens (summary only) | Same. |
| `summary` (Layer 1) | ≤ 300 chars (~80 tokens) | Schema; CI blocks at 301. |

## Worked example

A developer opens a TypeScript file and types a query into Cursor. Cost analysis:

| Component | Before any rule | With library v2 |
|---|---|---|
| System prompt (Tier 0 rules summaries) | n/a | ~5 × 80 = **400 tokens** |
| INDEX.md (loaded once per session) | n/a | **~3,000 tokens** |
| Scoped TypeScript rule summary (matched glob) | n/a | **~80 tokens** |
| Full rule content (loaded on demand only) | n/a | 0 tokens until @rule:<id> |
| **Total always-on cost per turn** | — | **~3,500 tokens** |

Compare to a naive "ship every rule's full content into the system prompt":
- 50 rules × ~800 tokens = **~40,000 tokens** always-on.
- ~11× larger; ~$0.36 vs ~$0.04 per Mythos-tier turn at $10/M input.

## CI enforcement summary

`registry-ci.yml` (Phase 6) runs the following token-economy checks per PR:

1. **`summary` length check** — every `*.rule.yaml` `summary > 300 chars` → block.
2. **Token-budget warn** — `tiktoken` counts every subagent's system prompt; warn at 80% of `token_budget.input_max`.
3. **Token-budget block** — same metric; block at 100%.
4. **INDEX.md regen + freshness** — regenerate from rule files; block if diff present.
5. **Surface-size lint** — total tokens of `.github/copilot-instructions.md`, `AGENTS.md`, `registry/INDEX.md` against targets above; warn at 80%, block at 100%.

## Anti-patterns to avoid

- **Inlining full `content` into adapter output.** Adapters write `summary` only. Full `content` is fetched by IDE on demand.
- **Reordering YAML fields to "improve readability".** This breaks prefix-cache and inflates cost. Use the schema's field order.
- **Adding asvs/iso/nist mapping arrays as long bullet lists.** Use the structured fields; their ordering is fixed.
- **Embedding multi-language code examples in `summary`.** Examples belong in `content`. `summary` is the agent-facing imperative.
- **Calling `$SECUREAI_LLM_ENDPOINT` for gate decisions.** It is for prose remediation only. The gate is deterministic.
- **Writing a Tier B chat prompt because Tier A "is too expensive".** Use Tier C — zero LLM tokens. ADR 0004 explains the choice.
